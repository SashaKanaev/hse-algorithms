# Makeheap

## Корректность и идея

Обе функции преобразуют исходный список в minheap и возвращают его же. Для элемента с индексом i родитель находится по индексу (i - 1) // 2, дети — 2 * i + 1 и 2 * i + 2.

- `makeheap_n_log_n`: добавляем элементы в уже построенную часть кучи по одному. Если новый элемент меньше родителя, поднимаем его вверх (`sift_up`).
- `makeheap`: идём от последнего узла с детьми к корню. Поддеревья детей уже являются кучами, поэтому достаточно опустить текущий элемент вниз (`sift_down`), каждый раз выбирая меньшего ребёнка.

## Сложность

| Алгоритм | Время в худшем случае | Доп. память |
|---|---|---|
| makeheap_n_log_n | O(n log n) | O(1) |
| makeheap | O(n) | O(1) |

В первом случае каждый из n элементов может подняться на O(log n) уровней. Доказательство для второго способа — в [proof.md](proof.md).

## Тесты и сравнение

Проверил пустой и одиночный массивы, повторы, отрицательные числа, прямой и обратный порядок, случайные данные. Проверяется свойство кучи, сохранение всех элементов и изменение исходного списка.

Медиана пяти замеров на одинаковых данных, время в мс:

| n | Данные | O(n log n) | O(n) |
|---:|---|---:|---:|
| 1000 | random | 0.202 | 0.182 |
| 1000 | sorted | 0.089 | 0.083 |
| 1000 | reversed | 0.758 | 0.211 |
| 1000 | equal | 0.087 | 0.084 |
| 10000 | random | 2.581 | 1.990 |
| 10000 | sorted | 1.006 | 0.851 |
| 10000 | reversed | 10.755 | 2.085 |
| 10000 | equal | 0.948 | 0.827 |
| 100000 | random | 25.077 | 19.186 |
| 100000 | sorted | 10.535 | 8.705 |
| 100000 | reversed | 147.332 | 21.451 |
| 100000 | equal | 10.024 | 8.855 |

На обратном массиве каждый новый элемент поднимается почти до корня. Поэтому разница заметно растёт с n. На отсортированном массиве и одинаковых элементах sift_up быстро заканчивается, и оба метода работают линейно.
