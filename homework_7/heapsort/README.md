# Heapsort

## Корректность и идея

Сначала строю maxheap снизу вверх. Максимальный элемент находится в корне. Меняю его местами с последним элементом неотсортированной части, уменьшаю размер кучи на один и просеиваю новый корень вниз.

После каждого шага правый суффикс отсортирован и содержит самые большие элементы массива, а оставшаяся часть является maxheap. Когда в куче остаётся один элемент, весь массив отсортирован. Сортировка выполняется inplace, функция возвращает исходный список.

## Сложность

Построение кучи занимает O(n) (см. [доказательство](../makeheap/proof.md), для maxheap аналогично). Далее n - 1 раз переносим максимум, просеивание занимает O(log n). Итого O(n log n) в худшем случае. На массиве равных элементов просеивание заканчивается сразу, поэтому время O(n).

Дополнительная память O(1): не создаём буфер, рекурсии нет.

## Визуализация

```text
[4, 1, 3, 2, 5]
[5, 4, 3, 2, 1]     построили maxheap
[4, 2, 3, 1] | 5
[3, 2, 1] | 4, 5
[2, 1] | 3, 4, 5
[1] | 2, 3, 4, 5
```

## Тесты и сравнение

Проверил пустой массив, один элемент, повторы, отрицательные числа, прямой и обратный порядок, случайные массивы. Проверяется результат и то, что сортируется исходный объект.

Сравнил с sorted() и merge_sort из homework_6. Медиана пяти замеров, миллисекунды:

| n | Данные | Heap | sorted | Merge |
|---:|---|---:|---:|---:|
| 1000 | random | 1.438 | 0.041 | 1.052 |
| 1000 | sorted | 1.484 | 0.003 | 0.725 |
| 1000 | reversed | 1.293 | 0.006 | 0.758 |
| 1000 | equal | 0.249 | 0.003 | 0.698 |
| 10000 | random | 21.516 | 1.014 | 14.758 |
| 10000 | sorted | 20.449 | 0.031 | 8.826 |
| 10000 | reversed | 18.592 | 0.058 | 9.319 |
| 10000 | equal | 2.563 | 0.026 | 8.674 |
| 100000 | random | 283.312 | 13.422 | 200.881 |
| 100000 | sorted | 274.094 | 0.356 | 108.455 |
| 100000 | reversed | 252.903 | 0.509 | 113.009 |
| 100000 | equal | 26.519 | 0.260 | 107.960 |

sorted оказался самым быстрым: он реализован на C и использует уже упорядоченные участки массива. На random наш merge_sort быстрее heapsort, но требует O(n) дополнительной памяти. На одинаковых элементах heapsort быстрее merge_sort за счёт раннего завершения sift_down.
