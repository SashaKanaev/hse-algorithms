# K-th minheap

## Корректность и идея

Реализовал `find_kth_largest` со своей кучей и `find_kth_largest_heapq` через heapq. В обоих случаях поддерживаю minheap из k самых больших элементов, которые уже встретились.

Сначала строю кучу из первых k элементов. Если следующий элемент не больше корня, пропускаю его. Иначе заменяю корень новым элементом и восстанавливаю кучу. Инвариант: после каждого шага в куче находятся k наибольших элементов просмотренной части массива (с учётом повторов). Поэтому после прохода по всему массиву минимальный элемент этой кучи является k-м по величине.

Исходный массив не меняется. Некорректный k вызывает ValueError.

## Сложность

Построение кучи занимает O(k). Проверяем оставшиеся n - k элементов, замена корня занимает не более O(log k). Общая оценка — O(n + (n - k) log k), или O(n log k) для k >= 2. При k = 1 время O(n). Дополнительная память — O(k) под кучу.

## Визуализация

nums = [3, 2, 3, 1, 2, 4, 5, 5, 6], k = 4.

| Шаг | Minheap (своя реализация) |
|---|---|
| Первые 4 элемента | [1, 2, 3, 3] |
| 2 | [2, 2, 3, 3] |
| 4 | [2, 3, 3, 4] |
| 5 | [3, 4, 3, 5] |
| 5 | [3, 4, 5, 5] |
| 6 | [4, 5, 5, 6] |

Ответ — корень кучи, 4. В heapq внутренний порядок элементов может отличаться, но инвариант и результат те же.

## Тесты

Проверил оба примера из условия, повторы, отрицательные числа, k = 1, k = n, один элемент, неправильные k и случайные массивы со всеми допустимыми k. В тестах использовал sorted(nums)[-k] как эталон, в решении сортировки нет.
