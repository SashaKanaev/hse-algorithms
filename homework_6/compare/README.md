# Compare

## Корректность и идея

Реализовал рекурсивные `merge_sort` и `quick_sort`. Обе функции возвращают отсортированную копию списка, исходный не меняют.

- **Merge sort** делит список пополам, рекурсивно сортирует части и сливает их двумя указателями.
- **Quick sort** выбирает последний элемент опорным, переставляет меньшие либо равные элементы влево и рекурсивно сортирует две части.
- Декоратор `timer` измеряет время через `perf_counter`, сохраняет секунды в `func.last_elapsed`, а результат функции не меняет. `benchmark` выводит медиану пяти замеров.

## Сложность

| Алгоритм | Время | Дополнительная память |
|---|---|---|
| Merge sort | O(n log n) всегда | O(n) для слияний и рекурсии |
| Quick sort | O(n log n) в среднем, O(n²) в худшем | O(log n) стек в среднем, O(n) в худшем, плюс O(n) для копии |

Merge sort всегда делит массив на две примерно равные части. Quick sort при неудачном опорном элементе может каждый раз отделять только один элемент.

## Визуализация

Для `[4, 1, 3, 2]`:

```text
Merge:
[4, 1, 3, 2]
  [4, 1]       [3, 2]
 [4] [1]      [3] [2]
  [1, 4]       [2, 3]
      [1, 2, 3, 4]

Quick (pivot = последний элемент):
[4, 1, 3, 2], pivot=2
[1, 2, 3, 4]  (pivot на индексе 1)
[1] | 2 | [3, 4]  ->  [1, 2, 3, 4]
```

## Тесты и сравнение

Проверил пустой и одиночный списки, повторы, отрицательные числа, отсортированный и обратный порядок, случайные массивы. Есть тесты декоратора, включая исключение.

Для `n=600` локальный запуск `python homework_6/compare/compare.py` (медиана 5 замеров, миллисекунды) дал:

| Данные | Merge | Quick |
|---|---:|---:|
| random | 0.613 | 0.405 |
| sorted | 0.424 | 11.799 |
| reversed | 0.554 | 8.790 |
| equal | 0.514 | 10.657 |

На отсортированном массиве, в обратном порядке и на одинаковых элементах последний опорный неудачен, поэтому quicksort работает заметно медленнее. Абсолютное время зависит от компьютера.
