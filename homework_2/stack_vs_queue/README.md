# Задача 1. Стек и очередь на основе связных списков

## Идея решения

Для реализации стека и очереди используется односвязный список. Каждый элемент списка представлен объектом Node, который хранит само значение и ссылку на следующий элемент.

В отличие от обычного списка Python, элементы здесь не хранятся в массиве. Каждый узел знает только следующий элемент через next.

Для стека используется принцип LIFO — последний добавленный элемент должен быть удалён первым.

Стек хранит ссылку head на верхний элемент. При push создаётся новая Node, её next указывает на старый head, после чего новая Node становится новым head.

При pop сохраняется текущий head, после чего head передвигается на следующий элемент через head.next. Таким образом удаление и добавление происходят только в начале связного списка.

Для очереди используется принцип FIFO — первый добавленный элемент должен быть удалён первым.

Очередь хранит две ссылки: head на первый элемент и tail на последний. Новый элемент добавляется после tail и становится новым tail. При dequeue удаляется head, после чего head передвигается на следующий элемент.

Если из очереди удаляется последний элемент, head и tail становятся None.

Дополнительно в обеих структурах хранится _size, который изменяется при каждом добавлении и удалении элемента.

## Оценка сложности

Для стека:

push — O(1)

pop — O(1)

peek — O(1)

is_empty — O(1)

Получение размера — O(1)

Все операции выполняются только с первым элементом списка, поэтому количество элементов в стеке не влияет на время выполнения операции.

Для очереди:

enqueue — O(1)

dequeue — O(1)

peek — O(1)

is_empty — O(1)

Получение размера — O(1)

Добавление выполняется через tail, поэтому для поиска конца списка проходить по всем элементам не требуется. Удаление происходит через head.

Память: O(n)

Для каждого добавленного элемента создаётся отдельный объект Node, поэтому количество используемой памяти линейно зависит от количества элементов.

## Визуализация

### Стек

Пусть последовательно выполняются:

push(1)

push(2)

push(3)

После push(1):

head
 ↓
[1] -> None

После push(2):

head
 ↓
[2] -> [1] -> None

После push(3):

head
 ↓
[3] -> [2] -> [1] -> None

Теперь выполняется pop().

Удаляется элемент, на который указывает head:

3

После этого head передвигается на следующий узел:

head
 ↓
[2] -> [1] -> None

Следующий pop() вернёт 2, после него pop() вернёт 1.

Получается порядок:

3, 2, 1

То есть стек работает по принципу LIFO.

### Очередь

Пусть последовательно выполняются:

enqueue(1)

enqueue(2)

enqueue(3)

После добавлений структура выглядит так:

head              tail
 ↓                  ↓
[1] -> [2] -> [3] -> None

Теперь выполняется dequeue().

Удаляется элемент, на который указывает head:

1

После этого head передвигается на следующий элемент:

head       tail
 ↓           ↓
[2] -> [3] -> None

Следующие вызовы dequeue() вернут 2 и 3.

Получается порядок:

1, 2, 3

То есть очередь работает по принципу FIFO.

## Тесты

Для стека проверяются:

обычная работа LIFO;

корректность peek без удаления элемента;

работа с пустым стеком;

корректность размера;

добавление нового элемента после выполнения pop.

Для очереди проверяются:

обычная работа FIFO;

корректность peek без удаления элемента;

работа с пустой очередью;

корректность размера;

повторное использование очереди после удаления последнего элемента.

## Корректность решения

Стек и очередь реализованы на основе односвязного списка.

Стек добавляет и удаляет элементы через head и работает по принципу LIFO. Очередь добавляет элементы через tail и удаляет через head, поэтому работает по принципу FIFO.

Для пустых структур pop, dequeue и peek вызывают IndexError. Размер хранится в _size и изменяется при добавлении и удалении элементов.

Отдельно проверяется случай, когда после dequeue очередь становится пустой. В этом случае и head, и tail должны стать None.
